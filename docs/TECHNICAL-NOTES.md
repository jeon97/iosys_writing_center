# 설계하면서 확인한 점

## 인증 방식과 로그인 정책 분리

외부 인증 시스템의 응답 형식이 달라도 로그인 실패 횟수, 계정 상태, 권한, 세션 정책은 동일하게 적용돼야 합니다. 인증 제공자와 로그인 정책을 분리하면 기관 추가가 기존 로그인 흐름에 미치는 영향을 줄일 수 있습니다.

## 세션에 필요한 정보만 저장

로그인 후 여러 화면에서 사용자 정보를 사용하지만, 사용자 객체 전체를 세션에 넣으면 정보 변경 반영과 보안 관리가 어려워집니다. 화면 접근에 필요한 식별자와 권한만 저장하고 상세 정보는 필요할 때 조회하는 편이 안전합니다.

## 로그 조회와 삭제 권한

접속 기록과 관리자 활동 기록은 개인정보와 운영 정보가 포함될 수 있습니다. 목록 조회, 엑셀 다운로드, 삭제를 각각 권한 검사하고 해당 작업도 감사 로그로 남겨야 합니다.

## 지금 다시 만든다면

- 기관별 인증 구현을 설정 기반 Provider로 분리합니다.
- 세션 저장소를 중앙화하고 만료·강제 로그아웃 이벤트를 기록합니다.
- 로그 내보내기를 대용량 비동기 작업으로 전환합니다.
- 보존기간 삭제를 예약 작업으로 운영하고 삭제 결과를 별도 보관합니다.
- JSP 편집 화면의 공통 동작을 재사용 가능한 프런트엔드 컴포넌트로 분리합니다.
